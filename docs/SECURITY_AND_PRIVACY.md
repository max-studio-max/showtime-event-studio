# Security and privacy

## Today

- **No secrets in the repo.** The app needs none; `.env*` is git-ignored and `.env.example` holds only reserved names.
- **Local storage only.** The workspace lives in this browser's `localStorage`. Anyone with access to the browser profile can read it. Export/import is plain JSON.
- **No outbound actions.** SHOWTIME never posts, books, buys, emails or spends. "Request availability" opens the user's own email client with a draft; external links open in a new tab with `rel="noopener noreferrer"`.
- **Minimised guest data.** SERVICE stores cohort counts only — no names, dietary or accessibility details.
- **Audit log.** Every event edit and status change is recorded with actor, time and (for status) a required reason. Editing an approved event withdraws approval by default.
- **Untrusted HTML.** The only `dangerouslySetInnerHTML` is the plan SVG generated by `planSvg`, which escapes every user-entered label.

## Required before multi-user use (not built)

Server-side auth with MFA, tenant isolation and role enforcement; encrypted storage and backups; server-held OAuth credentials with scoped consent; signed uploads with file scanning; CSP and rate limiting; retention policies and consent for any personal data; data export and account deletion. See `ARCHITECTURE.md` → *Not built yet*.

Accessibility and safety outputs are advisory: SHOWTIME does not certify fire/egress, structural rigging, acoustics or code compliance.
